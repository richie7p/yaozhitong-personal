# 團隊原作與個人新增貢獻

參考作品由原黑客松團隊完成，並非個人專題作者單獨製作。參考版本：`440850bc77e11419a98c1850beba5ac278d07233`，來源 <https://github.com/Sean-Fang178/yaozhitong-web-demo>。

| 領域       | 團隊原作／沿用構想                                | 個人專題版新增實作                                             |
| ---------- | ------------------------------------------------- | -------------------------------------------------------------- |
| 產品流程   | 藥袋辨識→確認→仿單→警語／交互作用→測驗→提醒／照護 | 保留流程概念，React 模組與行動介面重建                         |
| 前後端     | 原生前端與 Node/Hono 組裝服務                     | TypeScript 共用 schema、API v1、資料領域模組、部署分離         |
| 帳號與資料 | 原作 Demo 流程作為需求參考                        | Firebase 登入、UID 資料隔離、Firestore、跨裝置 API、管理員角色 |
| AI         | 引用官方仿單、不把沒記載解釋為安全的構想          | NVIDIA 文字／影像串接、結構驗證、語意支持審核、版本化個人快取  |
| 排程照護   | 提醒、打卡、家人關心                              | Cloud Scheduler、FCM outbox、一次性邀請、後端即時撤銷檢查      |
| 資料治理   | TFDA 作為藥品及仿單依據                           | 主檔匯入、仿單 hash／草稿／發布／版本淘汰、人工整理欄位        |
| 評估與工程 | 原作候選排序供比較研究                            | 邊界測試、Playwright 流程、合成資料工具、可重現評估格式        |

新應用以原流程為需求參考撰寫，沒有將原作的 `app.js` 或伺服器搬進執行服務。`tools/compare-ranking.ts` 的比較基準改編自原作 `findCandidates` 排序，已註明來源、作者與版本；它不重現原本的資料庫檢索。完整參考 checkout 保留在 `reference/yaozhitong-web-demo`，建置和部署均排除它。若後續直接搬用其他原作程式段落，應保留原作者與 Apache-2.0 聲明，並更新本表。
