# 藥智通 JCMIT 初步技術評估方案

2026-10-20 規劃；2026-10-21 更新執行狀態。目的為回答[論文架構](JCMIT-PAPER-PLAN.md)中的辨識忠實性、驗證機制取捨與流程可靠性；不量測個人用藥適當性或臨床效果。以下樣本量為原定工作目標；工具與已建立資料見[評估工具](JCMIT-EVALUATION-TOOLS.md)，實際結果見[本輪紀錄](JCMIT-EVALUATION-RESULTS-2026-10-21.md)。不足的獨立實拍及人工評核不可用重複執行替代。

## 版本與資料凍結

正式執行前保存程式 commit、編譯或映像雜湊、模型供應商與請求／回應模型、推理設定、溫度或未設定狀態、token 上限、請求與任務期限、重試政策、提示版本、仿單版本及資料集雜湊。雲端與本機結果各有環境欄，不混算。

現有紀錄的設定是 OpenAI `gpt-6-luna`、推理 `none`、`grounded-v13-complete-safety-literal-recognition`；正式評估仍須從該次有效設定記錄，不以文件預設值代替。模型內部實作與訓練資料不可由本專案保證固定；「未見資料」只指未參與本專案開發調整。

主要辨識與內容實驗預設在隔離的本機資料副本使用真實模型，故障注入使用假上游；兩者明確標記。雲端現有一份已發布來源，若另做雲端完整流程，需先列清該環境實際可用來源及測試情境，不能直接把本機十二來源的計畫寫成雲端覆蓋。

先用開發集 3 案確認工具與用量，再封存測試名單、次數及指標。正式測試發現問題時保留原批，標成該凍結版本結果；修改系統後用新的未參與修正資料做確認，不以成功重跑覆寫失敗。

## 資料與標準答案

### 藥袋照片

工作目標為 30 個獨立藥袋案例，每案 3 次，合計 90 次辨識。照片須取得使用權並去識別；涵蓋不同版型、藥品列數與文字品質，保留來源與挑選方式，明載屬便利樣本。現有 4 張歷史實拍只作回歸，不算新增 30 張。

同一原始藥袋的裁切、旋轉、壓縮或多次拍攝共用 `bagGroupId`，放在同一資料分組，不能當獨立藥袋增加樣本數。若有衍生的模糊／傾斜壓力測試，與自然拍攝結果分列。

在看模型結果前，逐筆藥品轉錄照片可見的藥名、含量、每次劑量、單位、頻次及途徑。每欄另外標為「可判讀」「未印出」「不可判讀」，寫清允許的標點、空白、數字與單位等價規則；不可把含量當服用劑量，也不可把目錄資訊補成照片標準答案。

只有身分可由可靠資料確認的案例才標正確許可證。缺廠牌、含量或足以區別的資訊時，列「身分不可判定」，不硬選目錄候選；來源與候選評估另報可判定分母。

### 仿單與輸入案例

規劃共 12 份來源，既有 8 份為開發來源，新收集 4 份為未參與調整來源，分層報告。保存許可證、官方 URL、取得日期、版本雜湊、實際頁面／區塊，以及是否需要人工轉錄。新來源的整理流程固定後才生成；若依輸出改過提示或規則，該來源改列開發資料。

每份來源事先準備 3 個使用情境，共 36 案：

1. 無額外健康背景的基本說明與理解題。
2. 一項原文有明確適用條件的合成背景；原文無此內容時，記錄為不支持案例，不補造條件。
3. 一項原文未支持的合成背景，檢查是否擴張成個人化結論。

每個情境只用合成背景，不提供實際病人資料。人類先列來源主欄、細項重點、必要條件／例外及不可從該段推出的主張；「未提及」不能等同「醫療上不成立」。

## 辨識指標

逐次原始輸出、欄位驗證後待核對輸出及使用者修改後資料分開保存。主要辨識結果使用「使用者修改前」資料，不能用改對後的資料計模型準確率。

| 指標 | 定義 |
| --- | --- |
| 藥品列 recall | 成功對應到的真實藥品列數 ÷ 照片可確認藥品列總數；漏掉的列保留在分母 |
| 藥品列 precision | 成功對應到的輸出藥品列數 ÷ 全部輸出藥品列數；誤增與重複列記錯 |
| 各欄正確率 | 各欄正確讀取數 ÷ 該欄可判讀數；留白或漏列均算未正確，逐欄報數 |
| 不應填值卻填入率 | 「未印出／不可判讀」欄位被輸出具體值的數量 ÷ 該類欄位總數；兩類分列 |
| 留白率 | 可判讀欄位被留白數 ÷ 可判讀欄位數；與前項並列，避免全留白看似安全 |
| 整袋完全符合 | 無漏列、誤增、重複、可判讀欄錯誤或不應填值的藥袋執行數 ÷ 全部藥袋執行數 |
| Top-1／Top-3 | 正確許可證位於第 1／前 3 候選的數量 ÷ 身分可判定藥品列總數；無候選算未命中 |
| 核對負擔 | 每袋需要修改的可判讀欄位數；作者依標準答案修正只能稱工程核對量，不稱一般使用者時間 |

對應藥品列須一對一，預先規定多藥袋與重複藥名的比對規則；錯誤候選另保留原因。主表同時列獨立袋數、藥品列數、欄位數與執行數，不以大量容易欄位掩蓋少數重要欄位。

## 說明與測驗的配對比較

主方案是在同一次生成中保存：

- **A：驗證前候選**，僅在隔離評估資料中保存，包含格式可解析但尚未確認的說明與題目。
- **B：最後發布內容**，經來源、條件、題目檢查及原文補齊後的內容。

兩者使用同一次候選，避免另呼叫模型產生隨機不同的答案。標記每項內容來源為模型、來源原文補齊或固定閱讀題；B 的內容可能新增、移除或改由原文提供，不能一概當作模型品質提高。

這是整個發布流程的前後比較，不能單獨歸因於某一條驗證規則。現有 `direct/grounded` runner 為兩次生成、同來源同提示的另一種比較；如採用，須另列實驗條件，不能和同次生成比較混算，更不能稱為有／無 RAG 比較。

人類標註者盡量不知道輸出屬哪一條件，隨機排序後依原文判定。可行時兩位先獨立判定，再記錄原始一致率、分歧與最後處理；只有一人時如實揭露。需臨床知識才能裁決的項目標為不可判定，不用模型自評補成人類判定。

| 指標 | 定義與必要分母 |
| --- | --- |
| 陳述來源支持 | 支持／不支持／不可判定陳述數，以及全部陳述數；支持率主表以全部陳述為分母，標註覆蓋率另列 |
| 必要條件遺漏 | 需要保留條件而漏掉的陳述數 ÷ 所有涉及必要條件的陳述數 |
| 來源重點覆蓋 | 正確傳達的預先標註重點數 ÷ 本案例應包含重點總數；開發／新來源分列 |
| 正確候選保留 | A 中受來源支持且在 B 仍有等義呈現的內容數 ÷ A 中受來源支持內容數；記錄不當刪除 |
| 資料不足與失敗 | 資料不足、無說明、無題、格式失敗、傳輸／逾時各類案例數 ÷ 全部預定案例數 |
| 題目品質 | 唯一明確正解、正解有依據、所有選項足以依指定原文判斷、解釋有依據、適用條件完整；逐項及全部合格數／題目總數 |
| 題目來源重點覆蓋 | 至少有一題合格題涵蓋的重點數 ÷ 預定測驗重點數；不把每主欄一題當全部警語覆蓋 |

題目品質對 A 的候選題及 B 的發布題分別計算。沒有題目的案例進入「無題」分母；生成完全失敗時不得填成題目品質 100%。規劃至少 30 道不重複題目，實際不足就照實報告，不追加抽樣直到得到足量好題。跨情境重複題另列重複率，不灌入獨立題數。

解釋若直接顯示原文，需判斷它是否確實支持該題正解，不能只檢查字串相同。原文閱讀題可評其忠實性與唯一答案，尚不能證明難度適中、能評量高層次理解或產生學習成效。

## 同版本完整流程與恢復

事先選定 10 個具有可確認藥品及可用來源的情境，每個 3 次，共 30 次。可以連結辨識批次中的執行，避免重複呼叫，但須保留相同 run ID。完整流程的來源可用條件與辨識資料集不同，不能把這 30 次成功率外推成任意藥袋成功率。

每次走完「上傳／拍照 → 辨識 → 操作者對照固定答案核對保存 → 說明與引用 → 題目錯答及改正 → 重新整理確認保存」。由作者或腳本執行的操作不計一般使用者效能。

- **首次完成率**：未需操作者額外重送或重試即完成的次數 ÷ 30。系統自動重試次數另列。
- **恢復後完成率**：在預定恢復步驟及上限內最終完成的次數 ÷ 30；不能覆寫首次失敗。
- **時間**：上傳到辨識可核對、送出學習到可讀、答案保存回應各自記錄；總系統等待時間排除閱讀與人工核對，操作總時間另列。
- **延遲統計**：成功與失敗分列，保留逾時終止時間；報中位數、P95、範圍及樣本數。P95 固定採 nearest-rank `ceil(0.95*n)` 的第 k 小值，小樣本尾端估計只作描述。
- **快取與啟動**：主要生成品質測試不使用應用生成結果快取；命中與未命中分列。供應商 token 快取另記。冷啟動須有實際證據，不能因等待一段時間就自行標為 cold。
- **用量與費用**：包含成功、重試、失敗與審核請求。缺 usage 記未知；牌價估算標日期和計算方法，與實際帳單分開。可算該批已知總費用／完成流程數，明列未知部分及雲端費用範圍。

故障注入另做五種，各三次，優先用隔離測試環境與假上游：

| 情境 | 注入方式與預期觀察 |
| --- | --- |
| 上游 429／5xx 後恢復 | 假上游依固定次序回應；確認有限重試、期限與最後結果 |
| 上游持續逾時 | 假上游延遲；確認期限內結束、可見錯誤及允許的後續恢復 |
| 工作已建立但回應遺失 | 控制傳輸層中斷；確認重送沿用同工作，不重複扣額度或寫入 |
| 查詢中斷與頁面重新整理 | 建立工作後斷線／重整再接續；核對原工作與已保存結果 |
| 無可用來源或來源不足 | 固定缺來源案例；正確顯示資料不足，沒有未支持說明、假題或錯誤成功 |

每種報正確處理數／3、恢復耗時、遺失及重複寫入數；資料不足的正確拒絕屬故障處理通過，不屬正常完整內容成功。不把故障注入結果加進自然服務可用率，也不把本機程序重啟稱為真實雲端程序中止。

## 統計與報告規則

辨識及完整流程先報第一輪的獨立案例數與分子／分母，再報三輪各自結果及同案例變動；內容的每來源三種輸入是不同情境，不是三次同輸入重複。辨識以 `bagGroupId`、內容以來源許可證／版本為群組；若提供信賴區間，按群組重抽樣，同群的照片、題目與重複執行一起抽取，不把 90 次當 90 個獨立藥袋。新來源僅 4 份時以逐來源描述為主，不對很寬或不穩定的區間作強結論。

任何比例的分母為零時記 NA，不記 0% 或 100%。無人類評核時語意支持率記未評估；不把引用字串通過率替代它。至少分析三類實際失敗，不只展示成功畫面。

這是小型便利樣本的初步技術評估，沒有事先效力分析，不以「顯著改善」「臨床安全」或「優於所有模型」作預設結論。若結果未改善，如實報告並解釋取捨。

## 每筆資料與實驗附件

正式研究紀錄以以下欄位為目標；現有 runner 的實際欄位與範圍見工具文件。它記錄輸入及相關程式檔案雜湊、Node 執行環境、原始回應、重試與完整原始 usage，仍不代表已具備人類評核或雲端部署測量：

| 類別 | 欄位 |
| --- | --- |
| 資料來源 | datasetVersion、caseId、bagGroupId／sourceGroupId、split、synthetic、permissionStatus、deidentified、imageHash／sourceHash、可判讀性與標準答案 |
| 執行設定 | runId、repeatId、condition、timestamp、environment、codeCommit、buildHash、provider、requestedModel、responseModel、reasoning、generationConfigHash、promptVersion |
| 輸出與過程 | 原始／驗證後欄位、候選、候選說明與題目、剔除原因、補齊來源類型、發布內容、cacheHit、attempts、errorCode、終止狀態 |
| 時間與成本 | 各階段開始／結束、總等待、input／output／reasoning／cached tokens、usage 是否完整、成本估算版本 |
| 人類評核 | pseudonymousReviewerId、評核者角色、各項判定、分歧、裁決理由、時間；AI 協助另外標記 |

私有工作資料已放在 Git 忽略的 `.local/jcmit-evaluation/`，包括 pilot、完整可用資料批次、標註修訂與失敗紀錄。公開附件只保留合法可分享且去識別的部分。帳號、token、照片個資及原始健康資料不進程式庫。原圖是否可再散布與人工標註是否完成須另外確認，不因可公開瀏覽就宣稱兩者皆完成。

可完成的投稿附件為：資料組成表、標註規則、去識別逐案輸出、失敗清單、統計產生方式、環境與設定雜湊。若原圖無法公開，交代取得方式及限制，另提供可分享的合成重現案例，但不得以它替代原實拍樣本。
