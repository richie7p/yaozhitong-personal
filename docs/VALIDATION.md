Playwright 流程：登入→手動建立並確認藥品→設定時間→今日打卡→產生邀請→另一獨立瀏覽器身份無法讀到私人藥品→接受唯讀照護→撤銷後無法繼續查看。另測一般使用者無管理頁權限、管理員可進入後台、375px 不橫向溢出。

新增瀏覽器流程涵蓋：健康資料編輯與另一個登入同步、藥箱新增／修改／處理／匯出、照片缺漏存草稿後人工確認、仿單原文、錯題重答、兩藥比對、AI 錯誤 JSON 保留問題與使用原輸入重試。另以独立實際服務測試帳號刪除畫面與背景清除。

每次 E2E 使用獨立資料目錄，NVIDIA 金鑰替換成僅能連向隔離假上游的測試值；部署入口不載入測試上游。一般回歸不呼叫付費模型。

## 本輪發現並修正

- PWA 打包插入資產清單時，格式整理使逗號位置改變，產生無效 JavaScript。改成獨立資產陣列，離線外殼重新通過。
- 登出管理員後登入一般帳號會停在管理頁；登出現在重設到首頁。
- 本機任務佇列限制同時 2 件，啟動立即恢復待執行／過期任務；排程檢查不重疊。
- Windows 跨程序刪除鎖檔時可能短暫回傳 EPERM，已加入有界重試；真實檔案多程序測試驗證不遺失已提交寫入。
- 影像模型曾將 5mg 含量填成空白處方的每次劑量。現在移除名稱／含量後再核對劑量原文，無依據時清空；空白頻次標題不視為用法。完整保留辨識原文與低信心提示。
- 多藥辨識偶爾在完整物件外加一層陣列；僅允許單物件拆封，其他模糊／錯誤型別仍拒絕。
- 真實模型曾對 7 條陳述回覆 8 個審核布林值。改要求每條陳述的固定 ID，檢查重複、缺漏與未知 ID，不能為了通過而截斷多出的判斷。
- 兩藥比對曾顯示與其中一款藥相關的飲酒警語。現在引用必須明確提及另一款藥品或主檔／人工別名中的成分，再送語意審核；一般饮食警語不能當兩藥證據。無法可靠對應藥物類別時保守不顯示，不猜成分。
- 生成快取與評估紀錄改用 `grounded-v3-pair-scope`，另納入已知藥品身分詞，避免沿用舊驗證規則／成分別名的結果。

## 困難影像開發案例

`tools/check-local-vision.ts` 新建 7 張合成開發圖片：清晰、模糊、偏暗、反光、缺劑量與頻次、不同含量、同張兩種含量。沒有使用原 50 張資料的保留測試集。修正後各情境最新一次均通過欄位檢查；藥名允許與含量分欄，原始逐字比對亦保留。

原始失敗包含 API 忙碌、錯誤外層格式與含量誤填劑量，保留在 `.local/reports/vision-challenges/results*.json`。這是開發過程回歸，不能將最新通過案例換算成真實影像準確率。

## 已覆蓋的風險情境

- 不同 UID 的藥品／任務／健康資料隔離；普通使用者拒絕管理端點；不接受自行指定 admin。
- 停用帳號、未驗證 Email、無測試資格、到期或重複邀請、撤銷家人授權。
- 不預填缺失劑量／頻次、未確認藥品與 PRN 不排固定提醒、測驗未完成仍可排提醒。
- 幻造引用、錯段落歸屬、字串符合但結論不受支持、空白驗證結果、沒有來源不呼叫模型。
- 不同健康資料／不同 UID 快取隔離；仿單版本修正後不命中舊快取、舊題目不能继续作答。
- 並行請求冪等、不同 payload 的 key 衝突、每日次數交易、50 席名額交易、並行重試。
- 修改藥品只停用相關排程與學習；歷史打卡保留、修正記錄可清除；打卡後取消待送提醒。
- 同一時段重複排程檢查去重，移除提醒時間與撤銷授權後取消待送通知。
- 刪除立即停用，正在執行的 AI 任務無法在清除後重新建立健康資料。
- NVIDIA 429 有限重試、網路逾時、錯誤 JSON、安全錯誤訊息。

## 正式比較實驗

`npm run fixtures` 產生的 50 張圖片為合成資料；100 題為自動來源檢索草稿。尚未完成真實資料收集與人工標註。初版合成圖片的保留集偏向缺漏情境，不能直接當正式分層評估設計。

### 排序比較

先固定每張影像的候選池與正確許可證，避免把檢索與排序差異混在一起：

```powershell
npm run compare:ranking -- data/evaluation/ranking.example.jsonl .local/reports/ranking-smoke.json
```

基準改編自原作的仿單加權排序，改善版使用藥名、含量與劑型。附的單一合成案例只用於確認比較工具會運作（它刻意展示有仿單的錯含量排前），不能宣稱改善了整體 Top-1。正式應分別報告固定候選池排序、完整檢索覆蓋率及影像端到端結果。

### 直接生成與證據驗證

正式 cases.jsonl 每行包含 `id`、`split`、`humanReviewed:true`、`deidentified:true`、`question`、已審核 `chunks`（段落 ID／原文／許可證／版本／頁碼／位置），可選 `context` 與 `kind`。工具拒絕將未審核的自動題目視為金標。

```powershell
npm run evaluate:run -- cases.jsonl direct .local/evaluation/direct.jsonl 5
npm run evaluate:run -- cases.jsonl grounded .local/evaluation/grounded.jsonl 5
```

兩條件使用相同模型、提示與來源檢索；direct 僅做格式解析，保留未驗證輸出到實驗檔，grounded 增加歸屬、原文與語意審核。這是驗證步驟的消融實驗，並不是無 RAG 對有 RAG。每次明確限制案例數，記錄 dataset hash、模型／提示版本、延遲和 token；再次執行略過相同案例條件。輸出只供人工標註，不顯示於正式用藥介面。

在各 claim 加上專業標註者的 `humanSupported:true/false`，再計算指標：

```powershell
npm run evaluate -- .local/evaluation/grounded-reviewed.jsonl .local/reports/grounded-metrics.json
```

工具輸出欄位正確率、Top-1／Top-3、字串引用通過率、有答案／失敗案例數、已人工標註陳述数、無依據陳述比例、p50／p95 延遲與 token。沒有相應金標欄位就回 null；沒有人工語意標註，不能用字串匹配率替代安全性結果。

實驗還需保留獨立測試集、標註分歧與專業裁決、樣本分布、成本、拒答／漏答比例、誤判案例與資料授權。尚未執行正式比較，不预填準確率。
