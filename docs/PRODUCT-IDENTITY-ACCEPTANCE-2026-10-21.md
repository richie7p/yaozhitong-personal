# 產品身分核對驗收（2026-10-21）

本輪本機與雲端驗收通過，來源版本為 `1d86b10ab71f4d6ddc4d43d15c96ef6c279c12af`。驗收重點是：使用者確認藥袋用法之後，仍須另以包裝資料核對產品，才能連結仿單、產生說明、測驗、問答或交互作用內容。雲端分別驗證資訊不足時的攔截，以及合成包裝資料齊全後的正向流程。

## 核對規則與使用流程

- **用法與產品分開確認。** 用法確認保留每次用量、頻次與途徑；搜尋結果、辨識信心、選取候選或候選已有仿單，都不能代替產品核對。
- **證據須由使用者另外對照包裝抄錄。** 可用包含前綴的完整許可證字號；或完整官方品名、官方含量與劑型，且三者在完整官方目錄中只能對上一個產品。保留廠牌、口味及規格差異，不以濃度換算推定相同產品。官方含量或劑型不足時，須改用完整許可證。
- **資料不足可以先保存。** 候選與部分抄錄資料、已確認用法會保留；畫面標示「產品待核對」，正式 `licenseNo` 保持空值。使用者可補拍、補資料後接續，核對本身不呼叫 AI、不扣 AI 額度。
- **補拍不覆蓋尚未保存的用法。** 原資料與核對輸入保留，新照片另作辨識，由使用者返回原資料補充。編輯保存沿用既有提醒行為：包含只補產品資料的修改，保存後也會停用原提醒；介面已說明須重新確認時間並排定。

## 驗收結果

| 情境 | 本輪確認的行為 |
| --- | --- |
| 名稱不完整、缺含量、缺劑型、只有許可證數字或證據互相矛盾 | 保持待核對，不因選定候選而通過。官方含量未知時，不能以空白或自行填入的含量完成核對。 |
| 完整許可證，或全目錄唯一的完整品名＋含量＋劑型 | 由伺服器核對後才建立正式產品連結；客戶端傳入「已確認」不能取代證據。 |
| 待核對產品直接呼叫生成 API | 回 `409 identity_unconfirmed`，在建立工作、扣額度及呼叫模型前拒絕。Worker、快取、重試與完成寫入也重新檢查。 |
| 沒有獨立證據的舊藥品 | 讀取時顯示待核對，須補證據；讀取不自動改寫或遷移原紀錄。 |
| 舊聊天、學習／仿單內容與歷史工作結果 | 不展示無法通過目前身分及版本檢查的舊回答，提供補資料入口。 |
| 開啟 AI 處理紀錄 | 文字工作列表只載摘要，展開時才重查單筆結果；收合再開也重新核對。重新整理前尚未完成的回應不能讓舊內容重新出現。 |
| 隔離環境服務重啟與刪帳 | 12 筆合成藥品及個人設定保留、舊 token 被拒、排隊與逾期執行工作恢復；待核對產品恢復後仍遭拒且模型呼叫為 0。刪帳後瀏覽器登出、舊 token 被拒、私人資料清除。 |

獨立複查發現的「空含量可能誤通過」及「歷史結果收合再開沿用先前結果」兩項問題已修正，並納入修正後的完整測試。

## 實拍範圍與限制

公開實拍的息咳寧照片資訊不足，應走「待核對、補拍或補完整包裝資料」分支；這是符合本輪規則的結果。不能補造照片上沒有的完整品名、含量、劑型或許可證，再聲稱真實產品已確認。成功確認及解鎖流程已有合成資料回歸，不能據此宣稱該實拍產品完成確認。

本輪核對驗證的是使用者抄錄資料與官方目錄的一致性，未驗證包裝真偽，也不是臨床準確率或正式環境無錯誤的保證。本文不收錄個資、機密或原始照片。
