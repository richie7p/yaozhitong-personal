- 仿單索引：[藥品仿單或外盒資料集](https://data.gov.tw/dataset/9117) 對應 `InfoId=39` 匯出，依許可證連到 `mcp.fda.gov.tw` PDF。
- 已取得 30 份官方 PDF。2 份完成 Codex 逐頁文字與來源核對，在本機發布供軟體流程測試；28 份仍是草稿。`data/leaflets/local-reviewed.json` 明確記錄技術核對範圍，沒有宣稱藥師審查。`collection-manifest.json` 是收集當時的草稿紀錄；`extraction-review.json` 記錄兩個 PDF 抽取器的逐頁文字覆蓋比較。

以上 30 份是收集工具從有效的錠劑／膠囊候選取得，**不是按臨床代表性設計的最終 30–50 款藥品集合**。首次收集不等同適合一般成人專題測試的選藥清單。

## 審核流程

1. 從後台開啟官方 PDF，確認許可證、名稱、含量、劑型與檔案來源一致。多含量共用仿單需確認文字提及的適用範圍。
2. 逐頁核對抽取文字、頁碼與段落順序，特別是表格、上下欄、腳註、否定詞、劑量與單位。掃描 PDF 可以在後台按原頁序補入文字；空白頁不應填入推測資訊。
3. 核對內容足以支援此版預期題目，並記錄版本與審核者。醫療答案與安全性主張仍需具資格人員檢查。
4. 勾選「我已核對許可證、原 PDF、頁碼與抽取文字」，發布。發布會切換該許可證的版本指標，先前版本保留為 retired。
5. 仿單變更後重新生成最新說明與測驗；舊問答作為歷史保留當時引用，不冒充新版本資訊。

本機 PDF 在 `.local/blobs/leaflets/`，原始檔不進 Git。雲端模式同一路徑為非公開 Storage 物件。可用官方網址及版本 hash 再取得；若官方檔案已變更，应建立新版本，不能沿用舊審核紀錄。

```powershell
npm run import:catalog
npm run collect:leaflets -- 30
npm run import:leaflet -- 'C:/data/source.pdf' '許可證字號' 'https://mcp.fda.gov.tw/...'
```

PDF 文字交叉檢查工具需 Python、pypdf、Pillow 與 Poppler：`python tools/verify-leaflets.py`。輸出在 `.local/reports/pdf-review/`，不會變更發布狀態。

## 專題資料集

`npm run fixtures` 會產生 50 張合成圖片與 100 題引用仿單片段的檢索測試草稿；都不寫入使用者帳號。圖片包含清晰、模糊、偏暗、傾斜、反光與缺漏欄位。虚構藥名和「軟體測試」標示刻意區別真實處方。

合成資料只用於程式驗證，不能替代 50 張經同意、去識別化的真實藥袋。問答草稿皆 `humanReviewed:false`，不能當專家金標。問答依許可證切開開發／測試集，避免同一仿單跨組；圖片初版切分仍偏向缺漏欄位，正式實驗需先建立分層抽樣且固定的獨立測試集，再調參，並記錄資料集版本。

正式收集需保留來源授權、去識別化檢查、標註者、預期欄位、藥品許可證、問題、答案、證據段落、開發／測試標記。不要把患者身份或藥袋照片加入版本控制。
