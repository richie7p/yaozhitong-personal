# 公開使用與驗收狀態

更新日期：2026-10-23。網站已更新至 [63ff843](https://github.com/richie7p/yaozhitong-personal/commit/63ff843edec7ccf050475ad5363245b38986b1e5)，Web 與 Worker 均已切換到新映像。所有完成信箱驗證的帳號可使用一般功能；每日 AI 額度維持每人 **20 次**、全站 **1,000 次**，以台北日期計算。

## 本輪修正

修正同一操作被多個後端重複派送，以及大量新任務爭用額度計數器的問題。相同操作只建立一筆工作、扣一次額度；不確定是否已派送時，使用原操作識別碼恢復。暫時忙碌回應會保留可重試的錯誤，不把失敗顯示成完成。

照片上傳先驗證登入、帳號狀態與信箱，再排隊讀取圖片，避免匿名未完成的上傳占住名額。目錄冷載入合併為一次，搜尋結果依查詢、含量、劑型及來源版本快取，保存時仍重新核對產品身分。

來源讀取保留原字串，修正 Unicode 句號、整欄引號及連續標點的處理。實測另發現模型把「勿駕車」改成「可能嗜睡時勿駕車」；新版攔截這類新增條件的說明及正確選項，已保存的同類錯誤結果也須重新產生，其他正常內容與答案保留。

收尾時修正歷史問答的誤隱藏：一般「使用時／服用時」不再被當成新增症狀門檻；若同句前面仍有「嗜睡時」等條件，則繼續攔截。原 20 筆問答離線重放僅恢復一筆誤判，兩筆確有條件弱化的紀錄仍被拒讀，所有原始結果保持相同。

歷史問答中的藥品資料若還在載入或讀取失敗，顯示對應的暫時狀態；成功取得清單且確實缺少該筆時，才顯示藥品已不在清單。桌面與手機回歸涵蓋延遲、失敗、重新讀取、原藥品恢復及真正缺少的情形。

獨立對抗覆核另外重現並修正四類問題：手動／搜尋建檔在已存成功但回應中斷後重試會重複新增；編輯或移除後晚到的仿單回應會顯示舊內容；刪帳與裝置轉移的競態；舊登出程序誤撤新帳號或其他分頁的推播。新增流程涵蓋補拍再返回、延遲成功與失敗、實際登入元件的登出事件及跨分頁鎖定。

新版也在正式雲端用一筆合成藥品實測：首個儲存已回傳 201 後刻意中斷回應，修改內容重試得到 409，恢復原內容重試則讀回同一筆；375px 行動版與桌面重新整理均保持一筆。驗收新增的合成資料已精確清理，原來源、既有資料快照及配額讀回一致，沒有產生新的 AI 任務。

跨分頁推播測試使用實際應用元件、瀏覽器 Web Locks 與本機合成 Firebase／FCM 邊界，尚未把它列為新版 Android 實際收件驗收。不支援安全協調的瀏覽器會顯示原因，站內提醒與登入仍可使用。

## 仿單與內容驗收

雲端新增 72 款官方仿單，合計 **3,593 款**；新增原檔及全文已讀回，既有來源沒有被替換。完整離線結構檢查為 2,847 款可讀、746 款待解析核對。可讀性、白話說明品質及測驗涵蓋範圍各自記錄。

兩款新仿單以 GPT-6 Luna／medium 完成原生離線測試，共 5 次請求、40,652 tokens，沒有逾時或供應商錯誤。逐條核對後修正上述一題條件錯誤；重播保留其餘 39 段說明與 8 題測驗。兩款的警語白話覆蓋仍是部分完成，保留完整來源供對照。

安瞳維生素洗眼液（026558）的單次正式雲端工作完成 17 段說明及五題測驗，3 次模型請求、16,446 tokens，約 44.9 秒；實際說明、全部選項與解釋已逐條對照來源。五題均測過答錯再答對、保存、重整及 375px 版面。兩個白話欄維持 `partial`；第 4、9 節未完整納入教學，跨眼重用液體與 30 秒洗眼限制仍只在原始全文中。

歷史問答誤判修正後，原先被隱藏的同一筆問答已在雲端桌面及 375px 重開，重新整理仍讀回原答案；兩筆確有條件弱化的歷史紀錄繼續攔截。原 17 段說明、五題及已保存的正確答案也在新版讀回一致。這次歷史問答讀回為唯讀，沒有新增 AI 任務或修改原紀錄，原紀錄、驗收帳號與全站當日用量均讀回一致。

之前六筆正式雲端說明／問答、14 題測驗及公開實拍藥袋流程的結果，保留於[前輪公開使用驗收](acceptance/public-access-learning-20261023.json)。照片缺少含量、劑型或完整許可證時仍要求補資料，不為開啟仿單而猜測產品。

## 多人使用與容量

使用官方 Auth／Firestore emulator、完整 66,521 筆目錄及 101 個合成帳號，完成 3,400 次混合操作；20／50／100 人情境的 p95 約 292／462／784 毫秒，沒有非預期錯誤。100 人分到兩個後端建立不同任務，也全部受理成功。另含 423 次額度及失敗恢復控制，其中兩次刻意注入派送失敗，均以同一操作恢復且只扣一次。

這組容量數據來自 `b6dd821`；收尾版本另外修正問答條件判斷、歷史藥品載入、新增藥品重試、仿單請求及推播帳號切換競態，另跑完整程式回歸及原紀錄雲端重開，沒有把它記成再跑一次大型容量測試。

以合成 JPEG 完成 35 次首次上傳，5／10／20 人情境均首波受理；20 人 p95 約 3.3 秒，並核對原始位元組、擁有者及跨帳號拒絕。這項數據測試上傳穩定性。原始未通過的雙後端壓測與修正前後對照仍保留在[負載驗收](acceptance/public-load-20261023.json)。

前版 `b6dd821` 的正式雲端讀取測試完成 180 次 GET：179 次 HTTP 200、一次在 15 秒期限到達時發生傳輸逾時；沒有 HTTP 5xx 或資料隔離失敗。同時段後端的 12 筆通知請求皆在約 0.23～0.32 秒回傳 200，但缺少逐請求追蹤，尚無法定位那次客戶端逾時。失敗結果保留，沒有重跑前 120 次；僅完成剩餘 60 次。續接後另做一次 29 次 GET 的有限診斷，全部讀完回應，28 筆登入請求均精確對上後端 trace，p95 約 1.32 秒；這組後測不能證明原逾時原因。桌面及 375px 測試另確認通知頁等待 45 秒後會結束載入、顯示錯誤，手動重新讀取可恢復，較晚到達的舊回應不會蓋掉新內容。

Cloud Run 仍各最少 0、服務最多 2 個實例，Web 並行數 40、Worker 2；原有容量、Secret 綁定、AI 模型與每日配額已逐項核對。這些測試不涵蓋大量民眾同時呼叫付費模型的正式雲端容量。

## 備份與還原

既有 Firestore 每日備份保留 7 天，先前已完成 5,606 份文件與 12 個集合的隔離還原核對。本輪補上 Auth 與檔案的加密備份：8 個帳號均成功隔離匯入，其中一個既有合成帳號完成原密碼登入、錯誤密碼及停用拒絕驗證；3,533 個原有檔案逐 generation 還原並核對 SHA-256，演練副本已精確清理。

每日 03:30（台北時間）的排程已建立；另從真正的 Scheduler 手動觸發並成功執行一次，約 8 分鐘完成最新 3,605 檔、472,924,686 bytes 及 8 帳號的加密快照。manifest 與帳號已解密讀回，72 個新增官方原檔也逐筆核對。這 72 檔的驗證範圍是備份讀回，實際隔離還原演練為前述 3,533 檔。

一般備份保留 7 天；照片延續原建立時間的 1 天期限，還原前排除過期、停用、刪除及無法確認擁有者的資料。實際來源目前沒有保留中的使用者照片，照片與 gzip 等恢復控制使用另外的六個合成檔案。工具、權限及實測範圍見[備份還原說明](BACKUP-RECOVERY.md)。

目前有四條告警規則，依選擇沒有通知管道或寄信；需在 Cloud Monitoring 查看。備份失敗記錄已與實際規則的篩選條件核對，尚未驗證通知或完整事件轉態。

## 程式驗證與保留缺口

本輪程式通過 1,743 項單元測試、173 項 Python 測試、238 項桌面／375px 行動版瀏覽器流程、81 組部署設定與 17 組 Hosting 設定檢查，以及本機生命週期測試。[程式 CI](https://github.com/richie7p/yaozhitong-personal/actions/runs/39942829811)與[本輪部署驗收](acceptance/public-stability-20261023.json)保留版本和範圍；真實 AI、隔離測試與正式雲端結果分開記錄。

仍有 **14,595 筆有連結資料未發布**，包含複雜版面、掃描圖、來源待釐清及原料藥等情形，另有 **3,059 筆缺索引或連結**；詳見[仿單資料盤點](TFDA-LEAFLET-INGESTION.md)。不可靠的來源與 AI 內容仍會被攔截，無法保證每款藥都有完整白話說明與測驗。

現有還原流程需要核對原專案最新的帳號刪除狀態，且備份與金鑰同在一個專案。整專案失去存取、大規模 Auth 誤刪、MFA／多租戶、新專案真人 Google OAuth，以及真實照護關係資料的完整災難復原仍未驗證。臨床適用性及正式醫療效益也尚未經研究驗證。
