# UI／UX 新版預覽

設計範圍：日常手機使用為主，另設研討會展示入口。

## 日常操作

- `#home`：直接進入拍藥袋與閱讀／測驗，保留今日排程和服藥紀錄。
- `#add`：照片預覽、辨識結果、核對用法三步。選擇候選後將焦點帶到核對表單；仍由使用者逐項確認，沒有辨識到的值保持空白。
- `#learning`：先選一份學習內容，再閱讀單筆說明。可直接跳用途、完整警語或理解測驗。
- `#learning?record=<id>&section=quiz`：重新整理仍停在指定紀錄／段落。進度以實際保存結果為準。
- `#jobs`：獨立查看處理紀錄、恢復與重試；個人設定中仍保留既有入口。

手機底部提供今日、藥品、拍藥袋、小教室、更多。家人照護、問答、紀錄及展示可從更多開啟。選單支援鍵盤循環與 Escape 關閉，收起後不會留下可聚焦的隱藏連結。

## 研討會操作

入口為 `#demo`。每次選一款已有說明的藥，按辨識、仿單說明、理解測驗三步展示。`record` 與 `step` 放在網址，重新整理仍可繼續。

- 明確標示「已保存結果」。切換步驟只讀取既有資料，不自動重送 AI 任務。
- 有對應辨識任務才顯示該任務入口；沒有辨識紀錄不冒稱辨識完成。
- 「現場拍一張藥袋」另進實際辨識流程；保存後帶著新藥品進入清單，由使用者開啟仿單說明，再帶新說明回展示。
- 顯示的已完成狀態與題數來自實際資料。測驗會真的保存答案，錯答、未保存或保存失敗不當成完成。
- 仿單主欄全文、每項引用、題目原文依據與個人處方的區分保留。測驗仍只抽查各欄重點。

## 本機隔離

此電腦的新版預覽在 8086，使用獨立的 `.local/seminar-demo-ui-preview-v1`，由既有八藥資料複製而來；不回寫 8085 的驗收資料。8085 的啟動捷徑、master 程式與既有資料保持原狀。

已準備好該資料的這台電腦，可雙擊新版資料夾中的 `啟動新版介面.cmd`。也可在新版工作目錄啟動：

```powershell
npm run build
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-seminar.ps1 -NoBrowser -Port 8086 -DataDirectory .local/seminar-demo-ui-preview-v1
```

再開啟 <http://127.0.0.1:8086/#home>。這些本機資料、照片與金鑰不隨 Git 同步；一般新裝置仍從空白資料開始，`#demo` 會顯示準備指引。

本次 UI 檢查使用合成測試服務與已保存結果，不為改版另行呼叫付費 AI。既有的公開照片辨識與臨床適用性限制仍以 README 的 v13 範圍為準；UI 改版不擴大原驗證範圍，也不要求整台電腦重開機。

## 本輪驗證

2026-10-20：445／445 單元測試通過，型別與建置通過。桌機與 375px 手機涵蓋 21 個案例、共 42 個執行組合：最終全套 40 個通過，另兩個因測試重複點選未變更的已答對答案而等不到請求；修正測試步驟後，在同一建置重驗 2／2 通過。產品正確地停用無須重送的答案。較早的舊標題與舊聚焦目標測試失敗也保留於本機報告，未以更改產品行為迎合舊選擇器。

新增案例包含手機主導覽／更多、單筆學習與深連結重載、錯答／改正／保存後刷新、最後一題完成焦點，以及合成拍照 → 保存新藥 → 產生說明 → 帶同筆內容回展示。合成案例使用隔離的模擬上游，不是新的真實照片辨識驗收。

最終 10 張桌機／手機截圖逐張檢視通過，沒有發現水平越界或阻擋操作問題；另核對 1.2 倍字級、照片預覽、候選核對與鍵盤焦點。這不是全面無障礙認證。本機原始證據在 `.local/reports/uiux-*` 與 `.local/ui-review/final-review.json`，不隨 Git 同步。

8086 的八藥／25 題已保存內容另通過 **64／64** 步桌機與手機回歸，包含展示三步、完整說明、每題錯答 → 原文 → 改正 → 重載與保存前後資料比對；0 新 AI 任務、0 外部 AI 呼叫、0 瀏覽器執行錯誤。完整報告為 `.local/reports/seminar-saved-demo-ui.json`。工具名含 service-restart，但本次沒有提供前一程序標記，因此只證明目前服務身分與保存結果，不證明新的服務重啟或 Windows 重開。最初未載入本機供應商設定的啟動檢查失敗另有保留，與通過的正式報告分開。
