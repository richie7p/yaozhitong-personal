最初盤點基於程式版本 `1ac3dc3d5727bddafa04ec22ab9c890bbe177b44` 及下列既有紀錄。2026-10-21 已補上評估工具、實拍參考答案草稿、小批及現有資料的擴大實測；批次版本、實際結果與未完成項目見 [初步評估紀錄](JCMIT-EVALUATION-RESULTS-2026-10-21.md)。指標分母與原定執行目標見 [評估方案](JCMIT-EVALUATION-PROTOCOL.md)，不要把規劃的樣本量當作完成量。

## 投稿條件

[JCMIT 官方 EasyChair 徵稿公告](https://easychair.org/cfp/jcmit2026)列明全文 4–6 頁、繁體中文或英文，需中英文篇名及摘要，摘要各不超過 250 字；包含緣由與目的、研究材料與方法、研究結果與討論、結論及參考文獻，提交 PDF。正式排版以官方 Word 範本為準。

徵稿公告已延長至 **2026-11-15，隨到隨審**；會議為 **2026-12-19**。[大會官網](https://jcmit2026.medinfo.org.tw/)仍列原截止日，且公告保留 11/13 繳費期限，因此延長投稿者的錄取、繳費安排仍須確認。建議內部完成日為 11/10、送出目標為 11/11，這是工作規劃，不是官方時程。

本題可對應徵稿主題的「人工智慧在醫療健康照護之應用」「醫療健康資訊系統軟體工程」「醫療健康照護資訊的教育和培訓」。不因大會主題包含 AI Agent，就把現行固定工作流程描述為已驗證的自主醫療代理。

## 建議題目與研究問題

中文題目：

> 藥智通：整合藥袋辨識、仿單來源核對與理解測驗之網頁系統設計與初步評估

英文題目草案：

> YaoZhiTong: Design and Preliminary Evaluation of a Web System Integrating Medication Bag Recognition, Leaflet Evidence Verification, and Comprehension Quizzes

三個研究問題：

1. **辨識忠實性**：在未參與本專案調整的藥袋上，哪些可判讀欄位能正確擷取？哪些缺漏或模糊內容會被錯填？使用者需要修改多少欄位？
2. **來源支持與覆蓋的取捨**：來源、條件及題目驗證之後，未受來源支持的內容是否減少？是否同時刪除了正確資訊、增加無題或資料不足的情況？
3. **流程可靠性**：同一凍結版本的辨識、核對保存、仿單說明、測驗與進度接續，完成率、耗時、用量及故障恢復表現如何？

理解測驗在本篇的評估對象是「題目品質與作答功能」。沒有使用者研究時，不以「提升理解」「改善服藥遵從性」或「降低用藥錯誤」作研究結論。

## 六頁論文架構

以下頁數合計約六頁，包含摘要、圖表與參考文獻；最後依官方範本調整。

| 部分 | 建議篇幅 | 要回答的問題與內容 |
| --- | --- | --- |
| 中英文題目、作者、摘要 | 0.75 頁 | 問題、系統方法、資料與評估設計、實際結果、範圍限制。結果數字待實驗完成再填。 |
| 壹、緣由與目的 | 0.75 頁 | 藥袋、仿單與學習紀錄的使用流程；相關系統與研究；本文研究問題及個人新增實作。 |
| 貳、研究材料與方法 | 2 頁 | 系統流程、來源版本與核對、辨識留白與人工確認、來源約束生成及原文補齊、題目驗證、資料集、比較條件、指標及記錄方式。 |
| 參、研究結果與討論 | 1.75 頁 | 新實拍逐欄結果、驗證前後內容品質與覆蓋、測驗品質、同版本流程與恢復結果；分析漏讀、錯填、拒絕與來源不足案例。 |
| 肆、結論 | 0.25 頁 | 只回答已測量的三個研究問題，說明適用範圍與下一步。 |
| 參考文獻 | 0.5 頁 | 官方資料、相關研究、沿用的原作與方法來源；依範本排列。 |

「研究材料與方法」建議依序寫：

1. **設計與資料流**：照片 → 結構化辨識 → 官方候選與使用者核對 → 已發布來源 → 說明與測驗 → 進度保存。提醒與通知紀錄列延伸功能，避免搶走三個核心功能的篇幅。
2. **來源與生成機制**：許可證、仿單版本與雜湊、PDF 頁碼／HTML 區塊；區分模型生成、原文直接顯示及固定閱讀題。經人工整理的影像仿單不可描述為通用自動 OCR。
3. **不確定性處理**：辨識缺漏留白、資料不足、候選身分不明、條件與否定詞檢查、來源不支持時的拒絕。
4. **評估設計**：開發集與保留測試集、來源標註、同次生成前後比較、重複實驗及故障注入；列出模型、提示與建置版本。

摘要先依「目的 → 方法 → 結果 → 結論」四段擬寫。結果段的樣本數、正確率、信賴區間及延遲須取自正式結果表，不用驗收通過數替代。

## 建議圖表

- **圖一：系統與證據流程圖**。標明模型處理、程式驗證、使用者確認、原文顯示及資料保存的位置。
- **表一：評估資料組成**。獨立藥袋數、照片數、藥品列數、來源數、開發／測試分組與不可判定資料。
- **表二：辨識結果**。逐欄正確數與分母、藥品列遺漏、應留白卻錯填、候選 Top-1／Top-3。
- **表三：內容與題目品質**。驗證前後的來源支持、條件遺漏、重點覆蓋、拒絕／無題及唯一答案。
- **表四：流程與恢復**。初次完成、恢復後完成、延遲、重試與重複寫入；正常測試及故障注入分列。

篇幅不足時合併表二、三；完整逐案結果另作去識別附件。不要用多張介面截圖取代評估表。

## 評估工具仍缺的能力

現有 [run-evaluation.ts](../tools/run-evaluation.ts) 與 [evaluate.ts](../tools/evaluate.ts)提供文字評估骨架，尚未找到正式人工核對案例集及正式比較結果。執行前需補：

- 影像辨識評估入口及照片標準答案合併；目前文字 runner 不會執行 OCR，也不帶出 `expectedFields`／`expectedLicenseNo`。
- `runId`、`repeatId` 與完整設定識別；目前同案例、條件、模型與提示再次執行會被略過，不能直接當重複實驗。
- 同次生成的候選、剔除理由、原文補齊與最後發布內容；分開計模型產生與程式補入的說明、題目。
- 每欄及每題分母、漏讀／錯填、拒絕／無題、來源重點覆蓋、人類標註覆蓋及群組統計。
- 真實供應商與回應模型、推理參數、提示／來源／建置雜湊、快取、重試、完整用量及缺失值；未回報用量維持未知。

現有 `direct` 與 `grounded` 兩組都提供相同來源檢索與提示，差別是後續驗證；只能稱驗證機制比較，不能稱「無 RAG 對有 RAG」。主方案採同次生成前後核對，避免多產生一次候選引入隨機差異；這項記錄能力仍需補齊。

## 作者與論文範圍待確認事項

- **作者與隸屬**：依實際學籍／任職填寫；若無隸屬，向主辦確認「獨立研究者」的填法。尚未代為聯絡主辦。
- **原作與貢獻**：[貢獻說明](CONTRIBUTIONS.md)指出原流程出自團隊黑客松作品。本文應清楚引用原作，區分個人新增的實作與評估；依實際研究貢獻確認署名／致謝，不能描述為全由一人首創。原作是否已正式發表須核對，以確認本稿新增內容及徵稿的未發表要求。
- **AI 使用**：如實說明開發及文字協助，作者核實引用、內容與結果；AI 代理不列作人類標註者。
- **相關研究**：仍需整理藥袋辨識、來源支持的醫療資訊生成、理解題品質及相關系統，查核原始論文後再寫差異；尚未建立足以宣稱方法新穎性的文獻比較。
- **研究邊界**：本稿評估資訊擷取、來源忠實性、題目品質與流程可靠性。臨床適用性、理解提升、服藥遵從性及大眾使用成效留待另行研究。
- **附件與展示**：原始藥袋、帳號、金鑰及有個資的紀錄不進 Git；公開圖片也需確認使用權與去識別。提供可重算的去識別資料、標註規則與程式版本。展示以[既有講稿](SEMINAR-PRESENTATION.md)為基礎，清楚標示即時與預存結果。
