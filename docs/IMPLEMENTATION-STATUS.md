## 設計上保留的限制

- 所有生成快取目前都按使用者隔離；尚未另做跨使用者的共用白話內容快取，避免個人健康資料誤共用。
- 掃描仿單目前支援人工補正文字；未提供後台影像模型 OCR 輔助按鈕。
- v13完整bundle總長上限22,000字、完整安全欄上限1,500字，超限／未完整結束先拒絕，不能靠裁字或漏頁宣稱完整。固定17個可識別安全主欄已以全文與逐欄至少一重點題補齊設計；不是每子項、任意新仿單或所有臨床情境的覆蓋證明。
- 數字與文字用量互斥；文字用量須有明確原始用量欄，藥名濃度或途徑不能冒充，辨識缺用量不預設一錠。確認仍要求頻次，PRN依需要時分流。
- 訪問健康頁面從雲端 API 讀取；不實作離線健康資料與離線同步佇列。Firebase 登入使用記憶體持續性，重整頁面可能需要重新登入。
- 由明確選擇的供應商文字模型負責生成及驗證；程式預設 NVIDIA，本機已明確啟用 OpenAI `gpt-6-luna` 並完成固定展示資料驗收。兩次模型判斷並不是獨立的醫療專業審查，仍需區分軟體來源核對與臨床驗證。
- 每次模型呼叫預設 45 秒，單一任務的生成、審核與重試共用 120 秒期限；同次呼叫的重試不重設其期限。逾時沒有回傳 usage 時，用量與費用未知。
- 通知採 lease 與相同 tag 去重；FCM 成功後、儲存送達狀態前若程序崩潰，可能重送。不能宣稱外部通知絕對 exactly-once。
- 晚到一天以上的家人提醒不補發；目前檢查台北當日到期紀錄。
- 測試／正式使用兩個獨立 Firebase 專案。腳本每個 Cloud Run 服務最多 2 個執行個體；web 和 worker 的上限分別計算。
- 每人／全站額度限制的是每日 AI **任務建立次數**（20／200），一次任務可能有生成、驗證和有限 HTTP 重試。這不是實際金額或 token 保證。
